> 我们准备在该服务器上运行 CIDR 论文正式性能实验，需要一个最长七天、可复现的独占测量窗口。请在窗口开始前让 parameter-curation worker 和两组 rsync 正常结束/退出；暂停进程仍占用资源，不能只保持暂停。也请维护者暂时干净停止 GPStore 与 TuGraph 常驻服务。我们不会擅自终止任何任务；请各所有者确认完成时间，待全部释放后还会进行连续 15 分钟的只读门禁采样，再开始正式实验。

## 清场后的验收顺序

1. 确认上述外部进程、传输与常驻容器均已退出或由维护者干净停止；记录停止前身份和后续恢复责任人。
2. 等待本轮 correctness-only import、hash 和 store gate 全部结束，确保没有本项目自己的大规模后台 I/O。
3. P03 连续采集 15 个、间隔 60 秒的样本；每个样本都要求 load1 `<5`、CPU idle `>95%`、MemAvailable `>=400 GiB`、`/data` util `<5%`、await `<5 ms`，且无未知大任务。
4. P03 READY 后运行 SF10 sentinel；QPS CV `<=3%` 且 P99 CV `<=5%` 才放行 P02B 和 S3--S8。
5. 正式性能任务严格串行；任何外部重负载回归都停止当前 attempt、保留失败证据并重新过门禁，不把受污染数据写入论文。

## 当前边界

- 我们能自动完成：持续只读监控、识别责任对象、记录进程/容器身份、在清场后自动执行 P03 与 sentinel。
- 需要用户或维护者协调：决定其他用户任务何时结束，以及是否/何时停止 GPStore、TuGraph 常驻服务。
- 不允许的替代做法：只看 load average、仅暂停进程、降低本项目并发、或把 correctness-only 的耗时当作正式结果。
